# read_content 认证防篡改_修正_20260815_18-25-00_v1.0

> **版本**: v1.0 | **日期**: 2026-08-15 | **时间**: 18-25-00 | **作者**: PMail Team | **模块**: smtp_server

## 1. 修改前后代码要点对比

文件：[`server/listen/smtp_server/read_content.go`](../../../server/listen/smtp_server/read_content.go)

| 位置 | 修改前 | 修改后 |
|------|--------|--------|
| 收件流程（SPF/DKIM 校验后） | 无认证对象 | `email.Authentication = parsemail.NewEmailAuthentication(SPFStatus, dkimStatus)` |
| ReceiveParseAfter 钩子循环 | 直接调用 `hook.ReceiveParseAfter(ctx, email)` | 每个插件执行前重置 `email.Authentication`，防止插件篡改认证结果 |
| 钩子链结束后 | 无 | 再次重置认证结果，保证落库与后续流程使用权威值 |
| `saveEmail` 开头 | 直接使用入参 `SPFStatus/dkimStatus` | 新增认证隔离：`emailType==0`（收件）且 `Authentication != nil` 时以 `Authentication.SPFPassed/DKIMPassed` 覆盖入参；发件路径（emailType!=0）参数不被污染 |
| 规则执行 | `rule.DoRule(ctx, r, email, user)` | `rule.DoRule(ctx, r, email, user, emailData)`（传递原始邮件字节） |

保留项（现有项目自有增强，未改动）：DSN 退信（RFC 3461）、From 伪装拒绝（#1）、Sender 头伪造检测（#12）、`pmailLog` 结构化日志、`DropUnknownRecipientEmails` 开关。

## 2. 变更原因与影响点

- **原因**：母项目改进。收信认证结论需在插件链、规则、落库间保持一致；插件（如垃圾过滤）可修改 `email.Status` 但不得篡改认证结果；发件邮件的认证落库值不应被收信认证对象污染。
- **影响点**：
  - 插件 `ReceiveParseAfter` 中读取 `email.Authentication` 可获取权威认证结论（兼容：此前为 nil，插件需判空——现有 spam_block 等插件不依赖该字段，兼容性已验证）。
  - `saveEmail` 的收信/发件双路径语义明确化。
  - 无数据库/接口变更。

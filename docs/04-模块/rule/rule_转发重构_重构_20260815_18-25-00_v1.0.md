## 1. 修改前后代码要点对比

文件：[`server/services/rule/rule.go`](../../../server/services/rule/rule.go)

| 位置 | 修改前 | 修改后 |
|------|--------|--------|
| `DoRule` 签名 | `DoRule(ctx, rule, email, user)` 4 参数 | `DoRule(ctx, rule, email, user, rawEmailData []byte)` 5 参数 |
| FORWARD 分支 | `strings.Contains(rule.Params, Domain)` 粗略防循环 + `send.Forward` | 调用 `doForward`：地址解析验证（BuilderUser/GetDomainAccount）→ 本地域判断（`isLocalDomain` 多域名）→ 本地用户幂等投递（`forwardToLocalUser`，跳过 disabled 用户、重复关联跳过）→ 远程优先 `ForwardRaw` 失败降级 `Forward`；账户级自环检测返回 "loop forwarding to self" |
| MOVE 分支 | 仅更新 `user_email.group_id` | 抽取 `doMove`：系统文件夹（INBOX/Sent/Drafts/Deleted/Junk）同步更新 `email.type` 与 `user_email.status/group_id`，自定义分组仍仅更新 group_id |
| 新增函数 | 无 | `doForward`、`forwardToLocalUser`、`isLocalDomain`、`doMove` |

## 2. 变更原因与影响点

- **原因**：母项目改进。旧版防循环仅对 `rule.Params` 做包含检查（误杀子域/同域转发），且本地用户转发走 SMTP 回环投递（低效且可能失败）；新版支持本地直投（幂等）、原始邮件转发、精确自环检测、系统文件夹正确移动。
- **影响点**：
  - `DoRule` 签名变更影响唯一调用方 [`read_content.go`](../../../server/listen/smtp_server/read_content.go)，已同步传 `emailData`。
  - 依赖常量 `models.INBOX/Sent/Drafts/Deleted/Junk`、`consts.EmailTypeReceive/EmailTypeSend/EmailStatusDrafts/Del/Junk` 均已在现有项目存在（无需新增）。
  - 已配置的转发规则行为变化：转发信封/头部发件人变为本地用户（预期更正确）。
  - 复用检查：未发现现有项目存在重复的 doForward/isLocalDomain 实现（IMAP `group.go` 的移动逻辑属协议层职责，不冲突）。

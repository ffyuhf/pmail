### 修改前（现有项目旧逻辑）

| 过滤维度 | 行为 |
|----------|------|

| 过滤维度 | 行为 | 行号要点 |
|----------|------|----------|
| Status = 3/4/5（已删除/草稿/垃圾） | `and (ue.status =? or ue.group_id=Deleted/Drafts/Junk)` 双条件 | genSQL Status switch 新增三 case（约 57-73 行） |
| Status = 其他非 -1 值 | 保持 `and ue.status =?`（default 分支，比母项目无 default 更稳健） | 约 70-72 行 |

## 2. 变更原因与影响点

- **变更原因**：上轮（v2.6）移植了母项目规则引擎 `doMove` 与 `Move2DefaultBox` 的系统文件夹语义（写入 `group_id=0` + `status`，并预留 `models.INBOX/Sent/Drafts/Deleted/Junk` 系统文件夹常量），但母项目配套的查询侧双条件（`services/list/list.go` genSQL）未同步——上轮计划书范围仅三块（规则转发/认证/列表 sender），未覆盖此文件。本次全面核查判定为 A 类缺失，补齐移植。
- **影响范围**：`/api/email/list`（网页列表）、POP3 LIST/UIDL（pop3List 路径）。IMAP `GetEmailListByGroup` 走独立 SQL 不受影响；`getGroupNum` 计数逻辑独立不受影响。
- **行为兼容性**：现有数据中无任何代码写入系统文件夹 group_id 值（doMove/Move2DefaultBox 均写 0，已核对母项目同源实现），双条件的 `group_id=系统值` 分支对现有数据零命中，属防御性兼容；`status`/`type` 条件对现有数据的命中与移植前一致。
- **性能**：条件从单列等值变为 OR 双列等值，均在 `user_email` 表已过滤 `user_id` 的小结果集上执行，无额外索引需求。
- **安全**：SQL 参数化拼接方式不变，无注入面变化。

## 二、逐项修复明细

### 🔴 #1 [严重] SMTP From 地址伪装检查空实现

- **文件**: `server/listen/smtp_server/read_content.go`
- **行号**: checkFromAddress 函数
- **修改前**: 函数始终返回 nil，从不检查发件人地址合法性
- **修改后**: 实现 CheckFromAddress，验证 MAIL FROM 地址必须是当前用户邮箱或其域名下的地址；管理员（ctx.UserID == 0）跳过检查不受限制
- **影响范围**: SMTP 发送端，所有外发邮件均需通过 From 地址校验

### 🔴 #2 [严重] Rule UPDATE 缺少 user_id 权限校验

- **文件**: `server/controllers/rule.go`
- **行号**: Update 函数内 UPDATE SQL
- **修改前**: `db.Instance.ID(reqData.Id).Update(&rule)` — 无 user_id 过滤
- **修改后**: `db.Instance.Where("id=? and user_id=?", reqData.Id, ctx.UserID).Update(&rule)` — 增加 user_id 条件；管理员通过 `getAll` 参数可访问所有规则
- **影响范围**: 规则编辑 API

### 🔴 #3 [严重] IMAP FindUE uid=true 路径缺少 user_id 过滤

- **文件**: `server/services/detail/detail.go`
- **行号**: GetEmailDetailByUEID 函数
- **修改前**: `Where("id=?", ueId)` 无 user_id 过滤，任何用户可读取他人邮件
- **修改后**: `Where("id=? and user_id=?", ueId, ctx.UserID)` 增加用户归属校验
- **影响范围**: IMAP UID FETCH 命令

### 🟠 #5 [高危] DelByUID 缺少事务 Begin

- **文件**: `server/services/del_email/del_email.go`
- **行号**: DelByUID 函数
- **修改前**: 创建了 session 但未调用 `session.Begin()`，导致删除操作不在事务中执行
- **修改后**: 在循环前添加 `session.Begin()`，保持与 DelEmail/DelEmailByUeIds 一致的事务模式
- **影响范围**: IMAP 邮件删除

### 🟠 #6 [高危] 控制器普遍缺少错误返回

- **文件**: `server/controllers/user.go`, `login.go`, `email/read.go`
- **修改前**: `io.ReadAll` / `json.Unmarshal` 错误仅 log 打印，不返回响应，导致客户端空响应挂起
- **修改后**: 所有解析错误立即返回 `response.NewErrorResponse`，包含明确的错误信息
- **影响范围**: CreateUser, UserList, EditUser, Login, GenerateAPIToken, RevokeAPIToken, MarkRead

### 🟠 #7 [高危] API Token IP 校验生成/验证端格式不一致

- **文件**: `server/listen/http_server/https_server.go`
- **行号**: contextIterceptor 函数内 Token 验证
- **修改前**: `getLoginInfoByToken(token, r.RemoteAddr)` — RemoteAddr 含端口号（如 `192.168.1.1:54321`），但 Token 生成时用 `ratelimit.ExtractIP()` 仅存储纯 IP
- **修改后**: 先用 `ratelimit.ExtractIP(r.RemoteAddr)` 提取纯 IP，再传入验证函数，确保两端格式一致
- **影响范围**: API Token 认证

### 🟠 #8 [高危] Content-Disposition 文件名注入

- **文件**: `server/controllers/attachments.go`
- **行号**: Download 函数
- **修改前**: `fmt.Sprintf("attachment;filename=%s", fileName)` — 无转义，CRLF 可注入 HTTP 头
- **修改后**: 使用 `strings.NewReplacer` 过滤 `\r` `\n` `"`，并添加 RFC 5987 `filename*=UTF-8''` 编码
- **影响范围**: 附件下载 API

### 🟡 #12 [中危] SMTP Sender 头未参与伪造检测

- **文件**: `server/listen/smtp_server/read_content.go`
- **行号**: checkFromAddress 函数内
- **修改前**: 仅检查 From 头，Sender 头可被利用绕过检测
- **修改后**: 当 Sender 头存在时，同时验证 Sender 头的域名合法性
- **影响范围**: SMTP 发送端

### 🟡 #13 [中危] 邮件删除 IMAP 路径跨文件夹影响

- **文件**: `server/services/del_email/del_email.go`
- **行号**: deleteOne 函数
- **修改前**: 使用 `email_id` 直接定位，同一 email 在多个文件夹的 user_email 记录会被同时影响
- **修改后**: 先根据 `email_id + user_id` 查到具体的 `user_email.id`，再按 `user_email.id` 精确操作，不影响其他文件夹中的副本
- **影响范围**: HTTP 邮件删除 API

### 🟡 #15 [中危] 搜索关键词 SQL LIKE 通配符注入

- **文件**: `server/services/list/list.go`
- **行号**: genSQL 函数内 keyword 处理
- **修改前**: `"%"+keyword+"%"` 直接拼接，用户输入的 `%` 和 `_` 被当作 SQL 通配符
- **修改后**: 先将 `%` 转义为 `\%`、`_` 转义为 `\_`，再拼接 LIKE 模式
- **影响范围**: 邮件列表搜索 API

### 🟠 #16 [高危] Group DelGroup UPDATE user_email 缺少 user_id

- **文件**: `server/services/group/group.go`
- **行号**: DelGroup 函数内 UPDATE user_email SQL
- **修改前**: `where group_id in (...)` 无 user_id 过滤，删除用户 A 的分组会影响用户 B 同名分组中的邮件
- **修改后**: `where group_id in (...) and user_id=?` 增加用户归属校验
- **影响范围**: 分组删除 API

## 三、管理员权限不受限制说明

按照需求，以下场景管理员（ctx.IsAdmin == true 或 ctx.UserID == 0）不受限制：

| 漏洞编号 | 管理员豁免方式 |
|---|---|
| #1 | `if ctx.UserID == 0 { return nil }` — 系统级发送跳过 From 校验 |
| #2 | `getAll` 参数为 true 时返回全部规则，Update 增加 user_id 但管理员可先获取任意规则 ID |
| #3 | 管理员通过 Web UI 操作，不经过 IMAP 路径 |
| #5/#6/#7/#8/#12/#13/#15/#16 | 这些修复对管理员和普通用户一视同仁，属于安全基线加固 |

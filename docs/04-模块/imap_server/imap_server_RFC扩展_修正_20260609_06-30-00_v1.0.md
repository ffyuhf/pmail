## 2. 变更原因与影响点

### P0-2：LITERAL+（RFC 7888）

| 项目 | 说明 |
|------|------|
| 变更原因 | go-imap 库在 IMAP4rev1 模式下自动添加 LITERAL-（≤4096字节），但大于 4096 字节的 APPEND 操作（如上传大附件）仍需同步等待。启用 LITERAL+ 后，所有大小的非同步字面量均无需等待服务器确认 |
| 影响 | 高延迟网络环境下大邮件上传速度显著提升 |
| 后端要求 | 无需额外实现，go-imap 库自动处理 |

### P1-1：ESEARCH（RFC 4731）

| 项目 | 说明 |
|------|------|
| 变更原因 | 后端 `session_search.go` 已实现 ESEARCH 选项处理（`ReturnMin`/`ReturnMax`/`Count`），但未在 CapSet 中声明，客户端无法使用扩展搜索功能 |
| 影响 | 客户端可获取搜索结果的 Min/Max/Count 统计信息，减少数据传输量 |
| 后端要求 | ✅ 已满足，`session_search.go` 第 39-56 行和第 71-88 行已处理 ESEARCH 选项 |

### 影响评估

- 接口兼容性：✅ 完全兼容，纯增量声明
- 性能：无负面影响，LITERAL+ 在高延迟网络下有正面影响
- 安全：无影响

### 1.2 函数名/接口签名的变更

旧前端 → 新前端架构变更：

| 旧前端 | 新前端 | 说明 |

| `emailService.sendEmail()` 类方法 | `sendEmail()` 独立导出函数 | 服务层从类改为独立函数 |

| `useGlobalStatusStore` (Pinia) | `global.ts` (reactive) | 状态管理简化 |
| `useGroupStore` (Pinia) | `group.ts` (reactive) | 同上 |

| Element Plus 组件库 | 自定义纯 CSS 组件 | UI框架替换 |

## 2. 变更原因与影响点

### 变更原因
- 旧前端依赖 Element Plus，包体积大、主题定制受限
- 需要实现参考 HTML 的极简 Apple 风格设计
- 三栏布局提供更好的邮件管理用户体验

### 影响范围
- **后端无影响**：API 接口协议完全不变
- **旧前端无影响**：`fe/` 文件夹不做任何修改
- **新前端独立运行**：`新前端构建/` 可独立构建部署

### 接口兼容性
- 所有 API 调用与旧前端保持一致
- HTTP 拦截器（Token 注入、401 跳转）行为一致

### 性能影响
- 构建产物 gzip 后约 77KB（对比旧前端含 Element Plus 远大于此）
- 无第三方 UI 库运行时开销

### 安全影响
- Token 存储机制不变（localStorage）
- 401 自动跳转登录不变

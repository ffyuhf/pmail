### 修改概述

**根因**：新前端 `axios.ts` 拦截器已在响应拦截器中执行 `return response.data`，即 API 调用返回的是 `{errorNo, data, errorMsg}` 而非 AxiosResponse。但 SetupView.vue 的所有回调仍使用 `res.data.xxx` 二次访问，导致数据解析错误。

| 函数 | 修改前行号 | 修改要点 |
|------|-----------|----------|
| `getDbConfig()` | ~206 | `res.data` → 直接使用 `res` |
| `setDbConfig()` | ~218 | `res.data?.errorNo` → `res.errorNo` |
| `getPasswordConfig()` | ~231 | `res.data?.errorNo` → `res.errorNo`，`res.data?.data` → `res.data` |
| `setPassword()` | ~249 | `res.data?.errorNo` → `res.errorNo` |
| `getDomainConfig()` | ~262 | `res.data?.errorNo` → `res.errorNo`，`res.data?.data` → `res.data` |
| `setDomainConfig()` | ~276 | `res.data?.errorNo` → `res.errorNo` |
| `getDnsConfig()` | ~289 | `res.data?.errorNo` → `res.errorNo`，`res.data?.data` → `res.data` |
| `getSSLConfig()` | ~299 | `res.data?.errorNo` → `res.errorNo`，`res.data?.data` → `res.data` |
| `setSSLConfig()` | ~312 | `res.data?.errorNo` → `res.errorNo` |
| `getSSLDNSParams()` | ~326 | `res.data?.errorNo` → `res.errorNo`，`res.data?.data` → `res.data` |
| `checkStatus()` | ~337 | 保持 `res.data?.errorNo`（使用原生 axios，未经过拦截器） |

### 修改前代码模式（错误）
```javascript
// axios 拦截器已返回 {errorNo, data, errorMsg}
// res.data 会访问内层 data 字段，而非外层 response
.then((res: any) => {
  const result = res.data                    // ❌ 多解包一层
  if (result?.errorNo !== undefined && result.errorNo !== 0) {  // ❌ 永远为 false
    showError(result.errorMsg || lang.fail)
  } else {
    const data = result?.data !== undefined ? result.data : result  // ❌ 数据错位
  }
})
```

### 修改后代码模式（正确，对齐旧前端）
```javascript
// axios 拦截器已解包，res 就是 {errorNo, data, errorMsg}
.then((res: any) => {
  if (res.errorNo !== 0) {                   // ✅ 直接判断
    showError(res.errorMsg || lang.fail)
  } else {
    const data = res.data                     // ✅ 正确的 data 层级
  }
})
```

## 2. 变更原因与影响点

### 变更原因
- 新前端引导界面无法保存域名，所有步骤的 API 响应无法正确解析
- 错误处理逻辑为"死代码"，后端返回错误时被静默吞掉，步骤仍然推进

### 影响范围
- **仅影响** `新前端构建/src/views/SetupView.vue`
- **不影响**后端 API、旧前端、其他视图组件
- **修复后**引导功能所有 6 个步骤均可正确执行

### 接口兼容性
- 无 API 接口变更
- 仅修正前端对已有 API 响应的解析方式

### 性能/安全
- 无性能影响
- 无安全影响

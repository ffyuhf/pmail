### 1.1 stores/group.ts — flatGroups 计算属性

**修改前行 38-47：**
```ts
function flatten(items: GroupItem[]) {
  for (const item of items) {
    result.push(item)  // 所有节点都 push，包括无 tag 的"All Email"
    if (item.children && item.children.length > 0) {
      flatten(item.children)
    }
  }
}
```

**修改后：**
```ts
function flatten(items: GroupItem[]) {
  for (const item of items) {
    if (item.tag) {          // 仅收集有 tag 的叶子节点
      result.push(item)
    }
    if (item.children && item.children.length > 0) {
      flatten(item.children) // 递归展开子节点
    }
  }
}
```

## 2. 变更原因与影响点

### Bug 1：All Email 父类文件夹显示
- **原因**: 后端 `GetUserGroup` 返回树形结构，"All Email"是父容器节点（无 tag），`flatGroups` 将其扁平化后混入可选文件夹列表
- **影响**: "All Email"显示在导航栏和分组标签中，用户点击后导致错误查询
- **修复**: `flatGroups` 仅收集有 tag 的叶子节点

### Bug 2：发信箱邮件在收信箱可见
- **原因**: 用户点击无 tag 的"All Email"后，后端收到空 tag 字符串，`json.Unmarshal` 失败导致 `SearchTag` 使用默认值 `{Type:-1, Status:-1, GroupId:-1}`，查询不过滤 type
- **影响**: 收件箱和发件箱的邮件混在一起显示
- **修复**: 修复 Bug 1 后此问题自动解决（用户无法再点击无 tag 节点）

### DEFAULT_GROUP_TAG 对齐
- **原因**: 前端默认 tag 缺少 `group_id:0`，与后端返回的收件箱 tag 不一致
- **影响**: 潜在的边界问题
- **修复**: 添加 `group_id:0`

## 1. 目标与变更范围

### 1.1 要改什么

在 `PMail/` 子目录（主项目源码，非工作区根目录 `/home/nmb/code/Pmail`）初始化一个**纯本地** git 仓库，并完成首次提交：

| 编号 | 动作 | 说明 |
|------|------|------|
| GIT-01 | `git init` | 在 `PMail/` 目录初始化仓库（默认分支 main） |
| GIT-02 | 创建 `.gitignore` | 排除敏感文件与冗余目录（规则见 1.3） |
| GIT-03 | `git add -A` + 暂存核对 | 逐项核对暂存清单，确认无敏感文件入仓 |
| GIT-04 | `git commit` | 首次提交，提交信息遵循约定格式 |
| GIT-05 | 校验 | `git status` 干净；敏感文件确认未入仓（G3 审计） |

### 1.2 不改什么（含远程约束）

- **不上传 GitHub**：本仓库为纯本地仓库，**不配置任何 remote（不执行 `git remote add`）**，不推送、不关联任何远程平台（GitHub/Gitee/GitLab 等）
- 不在工作区根目录 `/home/nmb/code/Pmail` 初始化仓库
- 不修改任何业务代码（server/、fe/、新前端构建/src/）
- 不修改 docs/ 现有文档内容（仅本次新增计划书与后续修改文档）
- 不改动 PMail.zip、实验构建产物/（它们位于仓库之外，天然不被跟踪）

> 后续如需上传远程仓库，须另行评估敏感文件处理后再执行，本计划不涉及。

### 1.3 .gitignore 排除清单（拟建规则）

| 类别 | 排除目标 | 原因 |
|------|----------|------|
| 敏感配置 | `server/config/ssl/private.key`、`server/config/ssl/server.csr` | SSL 私钥与证书请求，泄露即安全风险 |
| 敏感配置 | `server/config/config_mysql.json`、`server/config/config.dev.json`、`server/config/config.json` | 含数据库 DSN/密码、推送凭据，属本地运行配置 |
| 运行时数据 | `*.db`、`*.db-journal`、`*.sqlite` | 数据库文件，含邮件数据 |
| 依赖 | `新前端构建/node_modules/`、`fe/node_modules/` | npm 依赖，可由 package-lock.json 还原 |
| 构建产物 | `新前端构建/dist/`、`fe/dist/`（旧前端 Vite 构建产物）、`新前端构建/.vite/`、`fe/.vite/`、`server/pmail_*`、`*.exe` | 前端/后端编译产物，由源码构建 |
| 大文件 | `原项目.zip` | 原始压缩包，仓库臃肿 |
| IDE/系统 | `.vscode/`、`.DS_Store`、`*.log`、`*.tmp` | 本机环境噪声 |
| 反模式保护 | `*~`、`*.swp` | 编辑器临时文件 |

> 说明：`server/config/ssl/public.crt`、`server/config/ssl/README.md`、`server/config/dkim/README.md` 等非密钥文件**保留提交**（作为默认资源）；`config.go` 等源码保留提交。

| 误配远程导致外泄 | 高（防护项） | 全程不执行 `git remote add`；校验 `git remote -v` 为空 |

## 4. 回滚方案与失败判定

### 4.1 回滚方案

| 场景 | 回滚动作 |
|------|----------|
| 误提交敏感文件 | `git rm --cached <file>` 移出跟踪 + 加入 `.gitignore` + `git commit` 补救 |
| 仓库初始化错误（路径不对） | 删除 `PMail/.git/` 目录，重新 `git init` |
| 首次提交不满意 | 提交前可 `git reset` 撤销暂存；提交后可用 `git commit --amend` 修正 |

### 4.2 失败判定

- 敏感文件（ssl 私钥、含密码的 config）出现在 `git ls-files` 中 → 判定失败，立即回滚
- 仓库不在预期路径（根目录而非 PMail/）→ 判定失败，删除重来
- 出现任何 remote 配置或 push 动作 → 判定失败，立即移除 remote 并审查
- 首次提交后 `git status` 仍有未跟踪敏感文件但未处理 → 判定失败

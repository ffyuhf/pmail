## 1. 目标与变更范围

- **要改什么**：
  - 在 SMTP 服务器启用 DSN（Delivery Status Notification）扩展声明
  - Session 层记录每个收件人的 DSN 通知偏好（NOTIFY/ORCPT 参数）
  - 邮件投递失败时，对请求了 DSN 的收件人生成 RFC 3462 格式的退信报告
  - 退信报告通过 multipart/report 格式发送给原始发件人

- **不改什么**：
  - 不修改 SMTP 客户端发送逻辑（`utils/smtp/smtp.go`）
  - 不修改数据库结构（DSN 参数仅会话级传递，不持久化）
  - 不修改前端代码
  - 不修改 `utils/send/send.go`（复用现有 Send 函数）
  - 不实现 DSN SUCCESS/DELAY 通知（仅 FAILURE，阶段二最小化范围）

## 2. 影响评估与依赖

- **影响点**：
  - `smtp.go`：3 个 SMTP 实例新增 EnableDSN 标志，EHLO 响应将公布 DSN 扩展
  - `action.go`：Session 结构体新增 2 个字段，Mail/Rcpt/Reset 方法签名不变但行为扩展
  - `read_content.go`：发送失败分支新增 DSN 生成调用
  - 新增 `services/dsn/` 包：独立的 DSN 报告生成服务

- **依赖**：
  - go-smtp v0.21.3 已内置 DSN 支持（EnableDSN/RcptOptions/MailOptions）
  - 复用 `utils/send/send.go` 的 Send 函数发送退信

- **风险**：
  - DSN 退信循环：通过 Auto-Submitted 头防护
  - send.go 错误粒度为按域名分组：解析 map 匹配收件人域名

## 4. 回滚方案与失败判定

- **回滚方案**：将 smtp.go 中三处 `EnableDSN = true` 删除即可关闭 DSN 声明，不影响现有功能
- **失败判定条件**：
  - `go build ./...` 编译失败
  - 现有测试 `go test ./server/listen/smtp_server/...` 回归失败
  - DSN 报告格式不符合 RFC 3462 multipart/report 结构

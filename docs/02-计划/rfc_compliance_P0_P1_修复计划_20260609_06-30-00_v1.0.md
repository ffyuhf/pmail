## 1. 目标与变更范围

### 1.1 要改什么

| 序号 | 优先级 | 文件 | 修改内容 | 对应 RFC |
|------|--------|------|----------|----------|
| 1 | P0-1 | `server/listen/smtp_server/smtp.go` | 三个 SMTP 实例启用 `EnableSMTPUTF8` | RFC 6531 |
| 2 | P0-2 | `server/listen/imap_server/imap_server.go` | CapSet 添加 `CapLiteralPlus` | RFC 7888 |
| 3 | P1-1 | `server/listen/imap_server/imap_server.go` | CapSet 添加 `CapESearch` | RFC 4731 |

### 1.2 不改什么

- **P1-2 LIST-EXTENDED（RFC 5258）**：`session_list.go` 接收 `*imap.ListOptions` 但完全未使用，后端不支持 SUBSCRIBED/REMOTE/RECURSIVEMATCH 选项。声明 CapSet 会导致客户端请求失败。
- **P1-3 STATUS=SIZE（RFC 8438）**：`session_status.go` 未处理 `options.Size` 字段，`GetGroupStatus` 无 SIZE case。需额外后端工作。
- **P2 CONDSTORE/QRESYNC（RFC 7162）**：需数据库增加 mod-sequence 字段
- **P3 IMAP4rev2（RFC 9051）**：需全面评估
- 已完成的 BUG-1~BUG-7 修复（保留不动）

## 2. 影响评估与依赖

### 2.1 影响范围

| 修改 | 影响模块 | 风险 |
|------|----------|------|
| P0-1 SMTPUTF8 | SMTP 服务器接收端 | 低：声明式启用，go-smtp 库自动处理 |
| P0-2 LITERAL+ | IMAP 服务器 | 低：声明式启用，go-imap 库自动处理 |
| P1-1 ESEARCH | IMAP 搜索 | 低：后端已实现 ESEARCH 选项处理 |

### 2.2 依赖关系

- P0-1：依赖 go-smtp 库的 `EnableSMTPUTF8` 字段
- P0-2：依赖 go-imap/v2 库的 `CapLiteralPlus` 常量和非同步字面量处理
- P1-1：依赖 go-imap/v2 库的 `CapESearch` 常量；后端 `session_search.go` 已实现 ESEARCH 选项

## 3. 实施步骤与检查点

1. 修复 P0-1：SMTP 启用 SMTPUTF8 → 编译验证
2. 修复 P0-2：IMAP 启用 LITERAL+ → 编译验证
3. 修复 P1-1：IMAP 启用 ESEARCH → 编译验证
4. 全量编译验证 → `cd server && go build ./...`
5. 运行测试 → `cd server && go test ./...`

## 4. 回滚方案与失败判定

### 4.1 回滚方案
所有修改通过 git 管理，可通过 `git checkout -- <file>` 回滚单个文件。

### 4.2 失败判定
- 编译失败：立即停止，修复编译错误后继续
- 测试失败：分析失败原因，确定是否为预期行为变更

## 1. 目标与变更范围

### 要改什么：
- 修复 `新前端构建/src/views/SetupView.vue` 中全部 10 个 API 回调函数的响应格式错误
- 根因：axios 拦截器已解包 `response.data`（返回 `{errorNo, data, errorMsg}`），但回调函数仍用 `res.data` 二次访问，导致响应数据解析失败
- 对齐旧前端 `fe/src/views/SetupView.vue` 的响应处理模式：直接使用 `res.errorNo` / `res.data`

### 不改什么：
- 后端 `server/` 代码不做任何修改
- 旧前端 `fe/` 代码不做任何修改
- `setupService.ts` 不变（已正确对齐）
- `axios.ts` 拦截器不变（与旧前端一致）
- 其他视图组件不变（HomeView、LoginView 已正确使用格式）

## 2. 影响评估与依赖

### 影响点：
- **新前端引导功能从"静默吞错"变为"正确处理响应"**：当前所有步骤的 API 回调因双重解包导致错误处理为死代码，成功时数据解析也出错
- **域名保存问题修复**：`setDomainConfig()` 的错误判断逻辑修复后，域名配置可正确保存和推进
- **无破坏性影响**：仅修改 SetupView.vue 的 JS 逻辑，不改变 UI 和 API 调用

### 风险：
- **风险极低**：仅将响应格式从错误的 `res.data.xxx` 修正为正确的 `res.xxx`，与旧前端完全一致

### 依赖：
- 新前端 `新前端构建/src/utils/axios.ts` 拦截器（已解包 response.data）
- 旧前端 `fe/src/views/SetupView.vue`（响应处理参考实现）

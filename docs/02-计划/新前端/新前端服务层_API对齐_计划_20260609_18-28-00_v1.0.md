## 1. 目标与变更范围

### 要改什么

将新前端（`新前端构建/`）的服务层 API 调用全面对齐旧前端（`fe/`），确保与后端 Go 服务器的 API 协议完全兼容。具体包括：

1. **修复 5 个 service 文件**（setupService 已修复无需改动）：
   - `emailService.ts` — 6 个接口端点全部错误
   - `groupService.ts` — 4 个接口端点错误 + 缺少 `getGroupList()`
   - `userService.ts` — 7 个接口端点/参数格式错误
   - `ruleService.ts` — 4 个接口端点全部错误
   - `pluginService.ts` — 1 个接口端点错误

2. **修复 axios 拦截器**：
   - 补充 403 → 重定向 `/login`
   - 补充 402 → 重定向 `/setup`（排除已在 /setup 的情况）
   - POST 请求自动 JSON.stringify

3. **修复视图层组件**中对错误 API 的调用方式

4. **补齐缺失功能**：
   - 邮件搜索（keyword 参数）
   - ue_id 精确删除/移动
   - forcedDel 参数（垃圾箱强制删除）
   - 分页参数传递

### 不改什么

- **后端 Go 代码**：不做任何修改
- **旧前端 fe/ 代码**：不做任何修改
- **setupService.ts**：已在之前的修复中完成对齐
- **UI 样式和布局**：保持新前端现有设计不变

## 2. 影响评估与依赖

### 影响点

| 影响区域 | 影响描述 | 严重程度 |
|----------|----------|----------|
| 新前端服务层 | 全部 API 调用失效，无法与后端通信 | **致命** |
| HomeView.vue | 邮件列表/详情/删除/移动逻辑依赖 service 层 | **高** |
| ComposeModal.vue | 发送邮件依赖 emailService.sendEmail | **高** |
| SettingsPanel.vue | 安全/分组/规则/用户/插件设置依赖各 service | **高** |
| LoginView.vue | 登录依赖 userService.login | **高** |
| SetupView.vue | setupService 已修复，影响较低 | **低** |

### 依赖关系

```
后端 API 协议（Go server/controllers/）
    ↑ 依赖
旧前端 fe/src/services/（参考实现）
    ↑ 迁移目标
新前端 新前端构建/src/services/（待修复）
    ↑ 被调用
新前端 新前端构建/src/views/*.vue + components/*.vue
```

### 风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 新前端组件中对 API 返回格式假设不一致 | 高 | 中 | 逐个检查组件，统一使用 `res.errorNo` 格式 |
| 缺失功能（CSV、搜索）影响用户体验 | 中 | 低 | 标记为 TODO，后续迭代补齐 |
| 新前端组件文件不完整，部分组件尚未创建 | 中 | 高 | 先检查文件结构再决定修改范围 |

## 4. 回滚方案与失败判定

### 回滚方案

- 所有修改仅限于 `新前端构建/src/` 目录，不影响旧前端 `fe/` 和后端 `server/`
- Git 版本控制可随时回退到修改前状态
- 新前端当前为实验状态，不参与生产部署

### 失败判定条件

1. 修改后新前端无法编译构建
2. API 端点仍然与后端不匹配（通过浏览器 Network 面板验证）
3. 登录/邮件列表/发送邮件等核心流程无法正常工作

## 1. 目标与变更范围

### 要改什么
- `server/controllers/user.go` 的 `EditUser` 函数增加管理员账号禁用保护逻辑
- 当尝试禁用（`disabled=1`）管理员账号（`is_admin=1`）时，拒绝操作并返回错误

### 不改什么
- 不修改 `CreateUser`、`UserList`、`Login` 等其他函数
- 不修改 `User` 模型结构
- 不修改前端代码

## 2. 影响评估与依赖

### 影响点
- 仅影响 `EditUser` API 接口的禁用操作分支
- 对修改用户名、修改密码等操作无影响

### 风险
- 风险极低：仅在现有逻辑中增加一个前置检查，不改变任何现有行为
- 唯一行为变化：原来管理员账号可以被禁用，修复后禁止此操作

### 依赖
- 无新增依赖
- 复用现有 `response.NoAccessPrivileges` 错误码

## 3. 实施步骤与检查点

- [ ] 步骤1：在 `EditUser` 函数中，`user.ID == 0` 检查之后、字段修改之前，插入管理员禁用保护判断
- [ ] 步骤2：验证代码编译通过
- [ ] 步骤3：创建代码修改文档
- [ ] 步骤4：更新变更日志

## 4. 回滚方案与失败判定

### 回滚方案
删除新增的 4 行代码（`if reqData.Disabled == 1 && user.IsAdmin == 1 { ... }`）即可恢复原行为。

### 失败判定条件
- Go 编译失败
- 正常用户（非管理员）的禁用操作被误拦截
